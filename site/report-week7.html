Week 7 — The Greyscale Pattern Lab

Week 7 July 15, 2026 ToolsProgress

Every result so far points to the same weak spot: models read the shape of these puzzles almost perfectly but read the colors only partially. If color is the bottleneck, the fix is likely in the representation — so this week's tool lets us design and preview puzzle representations that don't lean on color at all: greyscale shades, hand-drawn glyphs, or uploaded icons for each of the values 0–9.

Open the Greyscale Pattern Lab →

In Plain Terms

Weeks 3–6 kept finding the same thing: an AI can look at one of these colored-grid puzzles and copy its shape back almost perfectly, but it gets a lot of the colors wrong. So the natural question is: what if we stop relying on color? Instead of ten colors, what if each value 1–9 were a distinct grey shade, or a little drawn symbol? This tool lets you invent those visuals by hand, drop in a real puzzle, and immediately see the whole thing redrawn with your design — so you can judge which representation looks clearest and best preserves the puzzle before we ever spend model time on it.

Why This Week

The Week 4 legend win and the Week 5–6 cross-model results told a consistent story: swapping models doesn't fix the color problem — the bottleneck is how the puzzle is drawn, not which model reads it. Adding a color legend already lifted accuracy once. The obvious next lever is the encoding itself.

Before running a formal experiment, we need a fast way to iterate on the encoding and eyeball it on real puzzles: does a greyscale ramp stay legible? Do hand-drawn glyphs read more distinctly than shades? Does the puzzle's structure survive the swap? The Greyscale Pattern Lab is that iteration surface — a design bench, not an experiment.

What It Does

You design a per-digit visual for each value 0–9, load an ARC-style puzzle JSON, and the tool re-renders every train/test grid with your design. Export the result as a PNG to compare encodings side-by-side. It is one fully self-contained HTML file — no dependencies, no server — and it is hosted here, so anyone can use it directly in the browser.

Three render modes

Grey shades — each value maps to a shade on a tunable grey ramp. Custom images — each cell is drawn with your uploaded or hand-drawn glyph. Original colors — the standard ARC palette, as a side-by-side baseline to compare against.

Draw or upload per value

An in-browser drawing canvas with an adjustable brush and a grey-shade slider for designing greyscale glyphs, or upload an image for any value. Value 0 defaults to a plain background but is editable.

Tunable & shareable

Adjust the grey ramp (dark/light ends, invert), background, cell size, gridlines, and an optional digit-label overlay. Paste or upload puzzle JSON, export the rendered puzzle as PNG, and your designs persist in the browser between sessions. Light/dark theme matches the rest of the site.

How to Use It

  1. Open the Greyscale Pattern Lab and click Load sample to render a puzzle immediately.
  2. For each value, click Draw to sketch a glyph or Upload an image — or just stay in Grey shades mode and tune the ramp.
  3. Switch between Grey shades, Custom images, and Original colors to compare how each encoding reads on the same puzzle.
  4. Paste your own puzzle JSON (standard train/test format) or upload a .json file, then Render.
  5. Export PNG to save an encoding for comparison or to drop into a future report.

Next Steps

With a design bench in hand, the plan is to pick the greyscale/glyph encoding that reads most clearly, render the puzzle set with it, and run it back through the Week 6 baseline tool — testing directly whether a color-free representation closes the perception gap that every model has shown so far.
